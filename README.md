# ScarletWell, live

Rutgers Health Hack 2026. Track: Wellness, Reimagined.

**Live demo: https://ddcxc6lcnn1te.cloudfront.net**
Engine API: https://6y5mquspjp.us-east-1.awsapprunner.com (try `/llm/status`)

ScarletWell today is an 18-item quiz on MyRutgers that returns a number. This project turns it into a living check-in: answer only what you want, get a friend's reply per dimension, get one next step tied to a real place or event near you (ranked by fit, then distance), watch your own trend, and, if you opt in, contribute to a k-anonymous campus picture that tells staff where need is rising before midterms do.

One product, two surfaces:

- **Student (Challenge 1):** check-in on the 8 wellness dimensions, warm feedback, one place and one event, a map, a trend, signals and nudges from devices the student connects, chat with voice.
- **Staff (Challenge 2):** an aggregate view only. Dimension by week heatmap, academic-calendar stressors, a dip detector tied to the overlapping stressor, insights with what to do by when, and a question box over the aggregate. Never an individual. Cells with n < 5 are suppressed in the engine.

Start with **`docs/SOURCE_OF_TRUTH.md`**. It is the single source of truth for what we build, why, for whom, with which data, and what we are not allowed to claim.

## Data and claims

- No PHI. Public data or synthetic data only. Synthetic check-ins are generated by `scripts/generate_wellness_synthetic.py` and labelled synthetic.
- No number in the UI or docs without a primary source. The engine attaches `source` to every metric. See `docs/EVIDENCE.md`.
- Wellness tool, not clinical. No diagnosis language, no red, orange or green meaning. Copy rules are in `docs/SOURCE_OF_TRUTH.md` section 2.5.
- Student data stays on the phone unless the student opts in. Wearable values never reach the engine or the aggregate.

## Run it locally

Prereqs: Node 20+ and Python 3.11+.

### UI only (fixtures, no backend)
```bash
cd app
npm install
npm run dev
```
Open the URL it prints (usually http://localhost:5173). The app uses hash routes, for example `/#/staff` and `/#/chat`. Data comes from `engine/fixtures/*.json`.

### UI against the live engine
Terminal 1, engine on :8000:
```bash
python3 -m venv .venv
.venv/bin/pip install -r engine/requirements.txt
cd engine && PYTHONPATH=. ../.venv/bin/uvicorn api.main:app --reload
```
Terminal 2, app:
```bash
cd app && VITE_USE_FIXTURES=0 npm run dev
```
Point the app at another engine with `VITE_API_URL=http://host:8000`.

### Checks
```bash
cd app && npm run typecheck && npm run build      # UI
cd engine && PYTHONPATH=. ../.venv/bin/pytest -q  # engine tests
python3 engine/fixtures/make_fixtures.py          # regenerate fixtures
```

## Configuration

Everything is optional. With no keys the engine serves templates and the app still works.

| Variable | Where | Effect |
|---|---|---|
| `VITE_USE_FIXTURES` | app | `0` calls the engine, otherwise fixtures |
| `VITE_API_URL` | app | engine base URL (default `http://localhost:8000`) |
| `VITE_GOOGLE_MAPS_API_KEY` | app, `.env.local` | Google Maps; Leaflet with OpenStreetMap is the fallback |
| `ANTHROPIC_API_KEY` | engine | Claude API for chat, feedback polish and food photo |
| `AWS_REGION` plus credentials, or `SCARLETWELL_BEDROCK=1` on an IAM role | engine | Claude on Amazon Bedrock |
| `SCARLETWELL_BEDROCK_MODEL` | engine | default `us.anthropic.claude-sonnet-4-5-20250929-v1:0` |
| `BEDROCK_GUARDRAIL_ID`, `BEDROCK_GUARDRAIL_VERSION` | engine | optional managed Guardrail on Bedrock calls |
| `ELEVENLABS_API_KEY` (and `ELEVENLABS_VOICE_ID`) | engine | text to speech and speech to text |
| `ANAKIN_API_KEY` | repo root `.env` | registry refresh scripts only; the engine does not need it to run |
| `ENGINE_LIVE=0` | engine | force fixtures |

Every model reply passes the forbidden-word check in `engine/recommend/llm.py` before anyone sees it, markdown is stripped, and chat is trimmed to 90 words at a sentence end. Without credentials each caller falls back to a template, and the reply's `method` field says which path ran.

## Keeping the resource registry current (Anakin.io)

Public Rutgers pages are read with [Anakin.io](https://anakin.io)'s URL Scraper. Every change becomes a proposal that a person approves. Put `ANAKIN_API_KEY=your_key` in a `.env` file at the repo root (git-ignored), or export it in your shell, then from `engine/`:
```bash
PYTHONPATH=. ../.venv/bin/python -m registry.refresh check     # which cited pages changed since last time
PYTHONPATH=. ../.venv/bin/python -m registry.refresh hours     # propose opening hours from each resource's page
PYTHONPATH=. ../.venv/bin/python -m registry.refresh events    # re-check events marked needs_confirmation
PYTHONPATH=. ../.venv/bin/python -m registry.refresh apply     # merge proposals marked "approved" in data/registry/proposals.json
```
`apply --complete` also approves proposals that read all seven days with the deterministic rules. It costs one credit per page, and a page shared by several places is read once per run. The staff view's "Resource registry" card (`GET /registry/status`) shows the result.

## Deploy to AWS

```bash
aws login                      # or set AWS_PROFILE
export AWS_REGION=us-east-1
export ELEVENLABS_API_KEY=...  # optional; omitting it turns voice off
export VITE_GOOGLE_MAPS_API_KEY=...   # optional, baked into the app build
infra/aws/deploy.sh
```

The script builds and pushes the engine image to ECR, creates or updates the `scarletwell` stack, builds the app against the engine URL, syncs it to S3 and invalidates CloudFront. It prints both URLs. No database and no student data are stored in AWS.

### A real-looking URL (custom domain)

CloudFront names (`*.cloudfront.net`) are assigned by AWS and cannot be chosen. To serve the app on your own hostname you need a domain you own. Two ways, both handled by `deploy.sh`:

**DNS in Route 53 (one command, certificate and DNS record created for you):**
```bash
SITE_DOMAIN=wellness.yourdomain.com HOSTED_ZONE_ID=Z0123456789ABC infra/aws/deploy.sh
```

**DNS somewhere else (Namecheap, GoDaddy, Cloudflare):**
1. In the AWS console, region us-east-1, Certificate Manager: request a public certificate for your hostname, add the CNAME it shows at your DNS provider, wait for "Issued".
2. Deploy with the certificate: `SITE_DOMAIN=wellness.yourdomain.com CERT_ARN=arn:aws:acm:us-east-1:... infra/aws/deploy.sh`
3. Add a CNAME from your hostname to the `CloudFrontDomain` stack output (printed by `aws cloudformation describe-stacks --stack-name scarletwell`).

The certificate must be in us-east-1 for CloudFront. Leave all three variables unset to keep the plain CloudFront URL. The engine keeps its own App Runner URL.

Notes:
- Enable Bedrock model access in the same region first. Check the model ID in the Bedrock model catalog; the default is an inference profile.
- The engine is public with open CORS. Fine for synthetic data; it needs auth before real use.
- The IAM policy uses `Resource: "*"` for Bedrock. Scope it down if this outlives the hackathon.
- Teardown: `aws cloudformation delete-stack --stack-name scarletwell`, then empty the S3 bucket and delete the `scarletwell-engine` ECR repository.

## Engine API

Shapes live in `docs/API_CONTRACT.md`, with matching fixtures in `engine/fixtures/`. Do not change a shape without updating both in the same commit.

| Route | Purpose |
|---|---|
| `POST /checkin/feedback` | per-dimension feedback for a partial check-in |
| `GET /resources` | fit-first, distance-second ranking |
| `POST /ask`, `POST /chat` | free text to dimension, places and events; conversational reply |
| `POST /nudge` | device or check-in signal to one step and the nearest open place |
| `POST /food/photo` | meal photo described kindly |
| `GET /aggregate`, `/aggregate/dips`, `/aggregate/insights` | k-anonymous cells, dips tied to stressors, what to do by when |
| `POST /aggregate/ask` | staff question over the aggregate |
| `POST /voice/tts`, `/voice/stt`, `GET /voice/status` | ElevenLabs voice |
| `GET /registry/status` | result of the last resource-registry refresh |
| `GET /llm/status` | whether a model is available and which |
